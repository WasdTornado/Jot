# 领域文档

## 布局与阅读顺序

本项目是一个 macOS 应用，由 Native 和 Web 两层共同实现，采用 single-context，不建立 CONTEXT-MAP 或多领域目录。

开始探索时：

1. 若存在，先读根目录 `CONTEXT.md` 和与本次修改相关的 `docs/adr/`。
2. 阅读 [PRODUCT.md](../../PRODUCT.md) 确认产品边界；界面变更阅读 [DESIGN.md](../../DESIGN.md)。
3. 用 [README.md](../../README.md) 核对当前开发、启动、数据路径和能力；按需查阅 [验收记录目录](../verification/)。
4. 读取任务关联的历史规格或新规格，并以当前代码和实际验证核对实施状态。

CONTEXT.md 与 ADR 尚不存在时正常继续，不为满足目录模板而预先创建空文件。术语或重要架构决策确实需要澄清时使用 `$x-domain-modeling`，将确认结论记录到根 CONTEXT.md 与 docs/adr/。

## 文档语义

- 产品文档描述范围，设计文档描述交互与视觉，规格描述目标，验收记录描述已经验证的事实；不能相互替代。
- `docs/superpowers/` 保留历史规格与实施计划，不因切换技能而删除或迁移。
- 2026-10-19 规格中的“尚未实现”、360×460 窗口、可配置全局快捷键和全页导出等属于早期计划，不能据此声称当前支持。现有窗口按设计稿实现，当前能力见 README 与近期验收记录。
- 文档与代码不符时明确指出差异；不能通过修改文档把未实现能力标成已完成，也不能把已过时的环境观察作为当前事实。
- 输出中的领域词汇沿用已确认定义；新增概念先判断是否需要，而不是任意换同义词。
- 与既有 ADR 冲突时，明确列出冲突和重新讨论的理由，不静默改写旧决定。
