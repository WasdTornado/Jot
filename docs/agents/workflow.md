# 开发工作流

采用已安装的 mattpocock-skills 插件，通过准确的 `x-` 技能标识调用。项目配置只记录本仓库约定，不复制技能源码或修改插件缓存。

## 按任务选流程

| 情况 | 技能与顺序 |
| --- | --- |
| 不确定用哪个流程 | `$x-ask-matt` |
| 报告缺陷或功能请求，需要评估 | `$x-triage` |
| 行为异常、偶发问题、根因不明 | `$x-diagnosing-bugs` → 修复 → 验证 |
| 新需求仍有实质歧义 | `$x-grill-with-docs` → 必要时 `$x-to-spec` |
| 已确认规格，需要跨轮拆分 | `$x-to-tickets` |
| 已明确的小任务或已有任务单 | `$x-implement`，在适合的行为边界使用 `$x-tdd` |
| 词汇或重要决策需要统一 | `$x-domain-modeling` |
| 实现完成后审查 | `$x-code-review` |
| 换会话继续 | `$x-handoff` |

只使用当前任务需要的步骤，不强制每次从需求访谈开始。用户当前指令优先于技能默认行为；尤其不自动提交、推送、创建远端对象或启动其他 Agent。

## 每轮工作

1. 明确用户可见目标、影响范围和验收方式；读取相关文档及当前改动。
2. 缺陷先复现、区分数据/桥接/原生/渲染层，再验证原因。跨模块先跟踪数据和确认消息，不靠猜测连续打补丁。
3. 可自动化的行为先补回归用例；纯视觉、低影响样式修改优先用实际原生窗口做前后对照，不写只检查实现细节的测试。
4. 最小范围实现，检查相关测试与类型；代码变更收尾执行完整检查。只改文档则检查链接和差异即可。
5. 审查本轮改动及与已有脏工作区的交互，不把前序未提交内容据为本轮成果。
6. 汇报变化、验证层级和剩余限制；需要跨轮的事项写回本地任务。

## 检查与运行

在仓库根目录执行：

- `node scripts/test.mjs`：TypeScript 检查、Web 测试、Swift 核心测试及原生加载恢复回归。
- `node scripts/build.mjs`：生成本地应用；这不证明真实 UI 验收通过。
- `node scripts/launch.mjs --qa <小写验收名>`：构建、安装到用户 Applications 并使用隔离数据启动；先正常退出运行中的随记。
- `node scripts/launch.mjs`：恢复使用正式数据的应用。
- `git diff --check`：检查补丁格式。

测试脚本使用项目约定的 Node 与完整 Xcode，不修改全局工具链。开发过程中优先跑相关测试，不在无变更、无疑点时反复运行全套检查。

## 数据与验收边界

- 正式数据：`~/Library/Application Support/TotNotes/`，不得用于故障注入、清空或演示内容。
- 测试数据：`~/Library/Application Support/TotNotesQA/<验收名>/notes/`；不得从桌面目录运行测试应用或读写测试数据，以免重复触发文件夹授权。
- 运行应用：`~/Applications/Jot.app`，不直接启动桌面工程内的 dist 产物。
- 保存失败时保留内容与窗口；更新前正常退出，不强制结束来绕过保存。
- 自动化测试、构建、签名校验、原生窗口、真实输入法、多显示器与发布验证分别报告。
- 中文粘贴或模拟 composition 事件不能证明真实输入法选词正常；多显示器几何单元测试不能证明真实硬件表现。
- 界面、输入、窗口生命周期或权限相关改动，在隔离原生应用中验收；无法完成的项目明确标记未验证。
- 验收摘要写入 `docs/verification/<日期>-<主题>.md`；只记录必要证据，不复制用户私人便签。
